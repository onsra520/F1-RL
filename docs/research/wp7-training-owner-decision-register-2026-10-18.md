## Exact execution and review workflow

1. For real reviews, complete D5 trust bootstrap and independently review/commit the public registry before pinning source. Pin a clean reviewed commit. Install the declared compatible environment; retain source/runtime/dependency identities. Use a new external evidence directory. Any later registry, source, configuration or runtime change requires restarting preparation and obtaining fresh bound reviews.
2. Run `python -B -m scripts.wp7_training_admission --profile spatial_rotating_owner_v3 --verify-software --verify-execution --execution-output <new-external-directory>`. Preserve stdout and exit code. Exit 2 means admission denied, even if engineering verification passes. The execution option actually runs the fixed 12 scripted TRAIN certificates/replays/Gym prefixes; it does not run PPO or create G3 robustness outcomes. Old certificates retain their original source binding.
3. Prepare a stable candidate without starting training: `binding = build_policy_execution(root, policy_id, profile='spatial_rotating_owner_v3')`; `prepared = capture_registered_run(binding, run_id=owner_assigned_id)`. Persist JSON externally using exclusive creation and `allow_nan=False`; retain `prepared['sha256']` independently. This captures a candidate, not a run or authorization.
4. After D1–D5 decisions/evidence, reviewers independently verify bytes/source/runtime and sign the exact `scientific_run_review` payload with protocol and manifest digests, bounded UTC issue/expiry. Use `review_message`'s domain-separated canonical bytes. Never commit private keys. Use only independently authenticated public identities already committed in step 1; the production registry is currently empty. Envelope-carried keys or verified booleans are not trust anchors.
5. Inspect run-bound review using `python -B -m scripts.wp7_training_admission --profile spatial_rotating_owner_v3 --run-manifest <prepared.json> --review <reviews.json>`. Repository-controlled trust registry and actual UTC apply; duplicate JSON keys/nonfinite values, unknown/revoked/expired keys, tampering and replay to a different run/protocol fail closed. Even valid reviews keep permission false.
6. `TrainingRunner(binding.configuration).run_registered(binding, run_manifest=prepared, review_envelope=envelope)` reuses the exact candidate identity, verifies current runtime/binding and denies before model/artifact allocation. Raw PPO create/load/learn boundaries remain independently denied. `evaluate_registered_cell(..., run_manifest=bound, review_envelope=envelope, expected_model_sha256=..., expected_run_manifest_sha256=..., artifact_directory=...)` verifies admission independently in parent and child; valid reviews cannot substitute for D4's absent permit. This is a denied-boundary verification workflow, not instructions to launch research.
7. Only a future explicitly approved D4 contract can define a positive execution path. Implement and independently review that agreed contract before issuing any permit. Do not set report booleans manually or reinterpret review signatures.
8. For separately authorized archival later, bind actual artifacts with `bind_run_artifacts`; verify an independently restored exact byte set with `python -B -m scripts.wp7_verify_run_evidence --manifest <bound.json> --expected-sha256 <independently-retained-digest> --artifacts <restored-directory>`. Optional offline review verification takes an independently authenticated `--trust-registry`; it grants no execution permission. Verify provider/ACL/independent operator evidence separately. Do not claim uploads from local comparisons.

Engineering closure ends with this checklist. External decisions do not justify repeated engineering expansion, automatic scientific approval or training.
