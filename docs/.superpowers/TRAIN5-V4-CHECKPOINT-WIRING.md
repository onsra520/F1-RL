# TRAIN-5 v4 final-checkpoint wiring

This is an engineering draft for the proposed 200,704-transition final checkpoint. It is not scientific admission, an owner-signed protocol, or permission to train or evaluate HELD-OUT.

`prepare_v4_runner` verifies the frozen pilot profile and v4 budget, preserves the pilot's 200,000 requested transitions and PPO/vector settings, and constructs a runner with intermediate checkpointing disabled. It accepts explicit PPO and sampling seeds and requires the output directory to be outside the checkout. The existing research admission guards remain in place. After the runner saves the final model, its observer requires exactly 200,704 actual transitions and a nonempty model file before the runner records completion. A mismatch fails the run.

For the proposed frozen-initialization cohort, the optional checkpoint identity is limited to the preproposed `C-seed0`, `B-seed1`, and `A-seed2` archives. Their pinned SHA-256 is checked during preparation and again on the exact bytes passed to the loader. Only policy weights are copied into a newly constructed model; the new model keeps its own optimizer, configuration, seed and zero timestep counter. Spaces, parameter structure and finite weights must match. The original archive is never a save destination. The draft runner records the selected identity and expected hash in its state; that local state is not independent attestation. Selection is a draft engineering option, not scientific approval or a signed assignment of replicates.

`evaluate_v4_runs` requires six run results, one per proposed cohort and replicate, with no intermediate checkpoints and the expected requested and actual steps. It hashes the six saved final model files and checks the episode records against those hashes before passing them to the existing v4 metrics evaluator. The run results and records are inputs, not independently authenticated evidence of training or evaluation. The evaluator's thresholds remain proposals and it grants neither training nor HELD-OUT permission.

Tests exercise the runner using mock models and synthetic episode records. No research policy is trained and no real development episode is evaluated. The original v3 evaluator, pilot YAML, model archives and source-locked scientific admission rules remain unchanged. The proposal still needs its separately reviewed protocol, admission, source-bound evidence and owner decisions before a scientific run.
