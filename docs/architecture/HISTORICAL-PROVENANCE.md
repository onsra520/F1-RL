# Historical provenance and current engineering attestation

The two WP3 historical records, historical replays, pytest receipts, source-binding keys, frozen models and manifests are immutable. Their recorded `f1rl/` paths identify the historical source; they are not aliases for the current package. `python -m scripts.evidence.verify_historical_records --history <restored-history>` validates both pinned raw record hashes, canonical source bundles, replay and receipt hashes, roster and provenance references, and all 12 model hashes. Its result is `HISTORICAL_RECORD_INTEGRITY_VERIFIED`; it explicitly reports that the original uncommitted source was not reconstructed. The grouped verification module exposes this integrity-only behavior. The receipt builders at `scripts/evidence/technical_acceptance.py` and `scripts/evidence/register_crash_terminal_v1.py` validate their inputs and refuse to reissue historical receipts, even if migrated file bytes happen to match the historical hashes.

The current-source schema `engineering_source_attestation_v1` is distinct. Run `python -m scripts.evidence.engineering_attestation --root . --output <new-file-outside-checkout>` on a clean full clone; use the same command with `--verify` to re-run its tests and model smoke and compare the submitted evidence. The attestation records the actual commit, tracked source paths and hashes, bundle hash, runtime versions, frozen model hashes, historical-record references, new pytest output and real PPO inference output. The attestation's own selected execution does not perform training; it is not a signature, scientific review, a replay of historical outcomes or a certificate for the full regression suite. A separate full engineering regression includes the user-authorized short learning tests on temporary models.

For telemetry restoration, follow `docs/research/FINAL-CONSOLIDATION-AUDIT.md` under “Reproducible historical bootstrap”. A source checkout contains the small inputs and 12 frozen models but not the raw telemetry. It requires the two SHA-256-pinned release ZIPs and a new destination for the full historical preflight. Do not change historical manifests, replay files, receipts or scientific admission to make restoration pass. The restored preflight is expected to leave the scientific gate BLOCKED.

WP7 `AUDIT_ONLY_PATHS` retains the exact historical `f1rl/` names. The historical source diff rejects migrated simulation paths and cannot certify the moved implementation as the original training source. The current engineering attestation is a separate check and grants no scientific approval, HELD-OUT access or registered evaluation authorization.

When using an installed wheel outside the repository, set `F1RL_PROJECT_ROOT` to the independent checkout that supplies the registered configuration and authored track assets. The installed package still checks the owner contract and pinned parent hashes. This is distinct from `F1RL_WP3_EVIDENCE`, which points to restored telemetry when historical preflight is required.
