## Root cause and implementation
1. **WP1 Lane Following:** prior `src/runtime/auto_drive.py` used route centerline for every target. Added road-local horizontal tangent/normal offset, road-width/vehicle-width/safety-margin cap, and validated `right` (default), `centerline`, `racing` style selection. Racing varies corner targets and curvature-limited speed, without bypassing collision.
2. **WP2 Vehicle Alignment:** `RacingScene.tsx` used arbitrary `pose.y + 0.74` and heading-only yaw; the physical frame position represents vehicle body centre. Removed arbitrary Y offset for authoritative frames, rendered full `[w,x,y,z]` quaternion as Three.js `[x,y,z,w]`, adjusted wheel geometry and preserved airborne position. Legacy non-physics build pose retains a documented visual placement fallback.
3. **WP3 Configurable Auto Drive:** vehicle speed, lookahead, braking, steering, grade and cornering tuning were hard-coded. Added frozen/strict Pydantic config schema, session-level snapshot, per-session API validation and replay config; frontend Drive settings, editable advanced fields, persisted settings, Reset and Normal/Racing/Hyper presets. Presets are bounded by physical vehicle max speed.
4. **WP4 Rendering:** heading-only sampling and nonuniform WebSocket arrivals could produce apparent stutter. Added quaternion SLERP and bounded frame-cadence interpolation with authoritative terminal and pause/reset behavior; camera and vehicle consume the same sampled render pose, camera uses frame-rate-independent damping.
